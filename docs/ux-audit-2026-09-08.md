# UX follow-up: local 0.12.22

The user authorized fixing issues from the native-app walkthrough and continuing
visual QA, then specifically reported delayed window dragging and choppy history
scrollbar dragging. Single-agent work. Public release remains 0.12.21; this patch
has not been published or installed over the normal app.

## Fixed

- Overview search is shown only on Overview, retains its query on return, and
  supports Ctrl+F. Champions and Matchups use consistent active-page terminology.
  The champion catalog now honors its visible sort choice and marks its active tab.
- Back/Forward remains visible on Live game. Compact live/champion-select headings
  leave room for the toolbar without clipping the draft footer at 1280x950.
- The overview is a keyboard-focusable surface: arrows, Page Up/Down, Home/End and
  Enter/Space select/reveal/open records. Its accessible children expose the profile,
  aggregate statistics, individual match statistics/actions and native filters.
  Selection has a teal focus outline; offscreen records are identified as offscreen.
  Preferences sections/selectors and Matchups lesson controls have meaningful names.
- Removed active champion-select copy directing users to retired build integrations.
- Scroll input no longer invalidates/repaints the entire dashboard. The new retained
  HomeOverview surface redraws only table rows/footer for a changed offset. Profile,
  summary, hero and title shell reuse pixels. Buffers are window-sized, not one per
  match, and are released on resize/disposal. Filters, refreshed data and disconnect
  invalidate the appropriate content; missing statistics remain unknown.
- Replaced per-cell TextRenderer calls into the large overview bitmap with direct
  GDI+ text drawing and reused the small fixed set of cell fonts. This removed the
  largest measured table-rendering cost. Avoided drawing the old title chrome under
  the dashboard's custom shell, repeatedly invalidating unchanged navigation tabs,
  and assigning identical maximize bounds during each window-location change.
- Wheel events are consumed once so nested history controls cannot double-scroll.

## Controlled performance evidence

Same InteractionPerformanceTests source, 1920x1040, 100 deterministic local test
records, warmed images, 60 offscreen input/paint cycles. Baseline binary is the
published 0.12.21 build in build/home-418cfa7bceab4c699551d0610a738c23.

| Workload | 0.12.21 total | Final local total | Approximate per-cycle change |
| --- | ---: | ---: | --- |
| Move window + repaint | 16,659 ms | 632 ms | 278 ms to 11 ms |
| Change history offset + repaint | 16,634 ms | 847 ms | 277 ms to 14 ms |

Earlier revised runs measured 689/949 ms for the same two workloads. These are
controlled UI rendering timings, not game FPS, a compositor trace or a claim that
live mouse responsiveness has been verified. AuditPerformanceTests also reduced
60 full offscreen DrawToBitmap captures from approximately 19 seconds (previous
release audit) to approximately 1.3 seconds. Reopening one match still retains
one detail page and approximately 38 USER objects, not a new tree for every click.

## Verification and limits

- verify-home passes: 769 app checks, 26 home-data, 14 rank-history, 132 dashboard,
  39 page-navigation, all-monitor window chrome, and 42 new UX interaction/cache
  checks. Tests cover filter/reset/disconnect state, accessible default actions,
  keyboard navigation through 100 records, wheel consumption, viewport-only redraw,
  unchanged buffer reuse, retained native controls and catalog sort/active state.
- verify-ui passed Preferences migration, native Save/Cancel hit targets on all
  three sections, dropdowns/toggles, draft layouts, Review, loadout compatibility
  and final-scoreboard rendering. verify-audit passed the 15 prior regressions,
  signed-update race, resource workload, mobile and archived integration tests.
- App-produced images were inspected at 1920x1040 (1080 monitor with taskbar) and
  1280x950: overview, filters/empty state, keyboard-selected final row, champion
  catalog, Matchups, live roster, champion select, final scoreboard and Preferences.
  Fixtures are clearly labeled and compiled only into standalone test programs.
- The preceding installed-app walkthrough could navigate via native keyboard/UIA,
  but native screen capture failed with SetIsBorderRequired / 0x80004002, and pointer
  actions lacked coordinate geometry. Visual follow-up therefore uses the app's
  own render harness. No successful live screenshot, mouse-drag retest, actual
  screen-reader session or fresh League game test is claimed.
- No normal installation, user preference changes, signing-key access, public
  release, website change, or renewed Riot/Overwolf integration is part of this work.
